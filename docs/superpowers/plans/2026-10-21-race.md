# Race Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `race`, a Wipeout-style anti-gravity racer, to the site's terminal: solo time trial with a weekly scoreboard, and online rooms for 2 to 4 players.

**Architecture:** Track geometry, ship physics and race rules are pure TypeScript modules with no three.js, so Node runs their tests and a lap-time script. A three.js view draws whatever state it's handed. Solo and online entry points glue those together like Tetris does. The Go API gets a `race` service package holding the room (relay only, like Tetris) and the scoreboard (Postgres via sqlc).

**Tech Stack:** TypeScript, three.js 0.186 (already a dependency, bloom from `three/examples/jsm`), Node 24 `node:test` with built-in type stripping, Go + Fiber + gofiber websocket, sqlc + pgx, Postgres.

**Spec:** `docs/superpowers/specs/2026-10-21-race-design.md`

## Global Constraints

- Do not run `git commit`. The user commits everything themselves. Leave all changes in the working tree.
- No new npm or Go dependencies.
- Pure modules (`race-rules.ts`, `race-tracks.ts`, `race-track-defs.ts`, `race-physics.ts`, `race-autopilot.ts`) import neither `three` nor `@/` paths, write relative imports with the `.ts` extension, and use no `enum`, `namespace` or constructor parameter properties (Node's type stripping rejects them).
- Units are metres, seconds and radians inside physics. Times crossing any boundary (HUD, socket, API, database) are integer milliseconds.
- Physics steps at a fixed `STEP = 1 / 120` s. Callers accumulate frame time and clamp each frame to 0.1 s.
- Keyboard only. No `PADS` buttons for race.
- Esc is handled by `game-window.tsx` as today and always closes the game.
- UI copy is lowercase and plain, matching Tetris and Tron (`need at least 2 players to start: send the invite link to a friend`).
- Track ids: `coaster`, `skyway`, `tidal`. Ship ids: `vega`, `kestrel`, `lancer`, `wisp`, `torch`. 3 laps per race.
- Name rule, same in Go and TS: trim, collapse inner whitespace runs to one space, then match `^[\p{L}\p{N}_ -]{1,16}$` counting code points.
- Boost meter: starts full, held key boosts and release stops at once, passive refill, each pad +0.2 and a short kick. Starting numbers: full meter lasts 5 s, empty to full refill 20 s, Vega boost multiplier 1.5.
- Lap targets with Vega: throttle only, no boost, no shortcuts 85 to 95 s. Smart driving 65 to 70 s. Ship spread within 4 s per lap per track, 5 s at most.
- Pads: 6 to 8 per lap, never closer than 8 s of Vega driving apart along the racing line (ramp pads count).
- Water: top speed × 0.85 while on it.
- Week starts Monday 00:00 UTC. Board shows top 10, one entry per lower-cased name.
- Online: 2 to 4 seats, countdown 3 s, 30 s cut-off after the first finisher, then DNF.

## Review Focus

1. **A backgrounded tab.** The browser stops animation frames, then hands back one huge `dt`. A ship must not tunnel through walls, checkpoints or gaps. Expect the frame clamp to 0.1 s, and in solo, auto-pause on `blur`. Pinned in Task 3 (`advance clamps a 5 s frame`) and Task 9 (pause on blur).
2. **Driving the wrong way over the line.** Reversing across the start line and back must not count a lap, and neither must a lap that skipped a checkpoint. Pinned in Task 3.
3. **A room where the race never ends.** If the host leaves mid-race, every racer leaves, or nobody finishes, the race still ends and the room goes back to the lobby. Expect a `MaxRace` of 8 minutes. Pinned in Task 10.
4. **A sleeping scoreboard server.** The free API host takes up to a minute to wake. The result screen must show times and the menu at once, the board must show `loading…`, then the board or `scoreboard offline`, and Play again must never wait on it. Pinned in Task 9.
5. **Names that only look valid.** Emoji, zero-width characters, a 17-letter Cyrillic name, or only spaces must be refused with a message, the same way in Go and TS. Pinned in Task 1 and Task 7 with a shared table of cases.

**Interfaces:**

```ts
export type Vec3 = [number, number, number]
/** Position, forward tangent, surface up, right. Unit vectors, right = forward × up. */
export type Frame = { p: Vec3; t: Vec3; n: Vec3; r: Vec3 }

/** Authoring input. Segment i runs from points[i] to points[i + 1]. */
export type PointDef = { p: Vec3; roll?: number /* radians, added to the transported up */; width?: number }
export type PathDef = { points: PointDef[]; closed: boolean; water?: number[] /* segment indices */; gap?: number[] }
export type PadDef = { path: number; seg: number; at: number /* 0..1 along the segment */; x: number; launch?: boolean }
export type BranchDef = { path: number; from: number; to: number /* segment indices on path 0 */; kind: 'shortcut' | 'drop'; side?: -1 | 1 }
export type TrackDef = {
  id: TrackId
  paths: PathDef[] // paths[0] is the closed main loop, the rest are branches
  branches: BranchDef[]
  pads: PadDef[]
  checkpoints: number // how many, spread evenly on the main path outside branch spans
  colors: [string, string]
}

export type TrackPath = {
  closed: boolean
  length: number
  /** One sample per SAMPLE metres. Flat arrays, 3 floats per sample for each vector. */
  p: Float32Array; t: Float32Array; n: Float32Array; r: Float32Array
  width: Float32Array
  /** Signed lateral curvature, 1/m: positive turns right. */
  curve: Float32Array
  water: Uint8Array
  gap: Uint8Array
}
export type Branch = { path: number; from: number; to: number /* metres on main */; kind: 'shortcut' | 'drop'; side: -1 | 1 }
export type Pad = { path: number; s: number; x: number; launch: boolean }
export type Track = { id: TrackId; paths: TrackPath[]; branches: Branch[]; pads: Pad[]; checkpoints: number[]; colors: [string, string] }

export const SAMPLE = 1 // metres
export const DEFAULT_WIDTH = 16
export const PAD_LENGTH = 6
export const PAD_HALF_WIDTH = 2.5
export const OPENING = 30 // metres of missing wall at a shortcut's entrance and exit
export function buildTrack(def: TrackDef): Track
export function frameAt(path: TrackPath, s: number, out?: Frame): Frame // interpolated, wraps when closed, clamps when open
export function sampleIndex(path: TrackPath, s: number): number
export function worldPos(track: Track, path: number, s: number, x: number, y: number): Vec3 // p + r·x + n·y
```

- [ ] **Step 1: Write the failing tests** in `race-tracks.test.ts`, with small inline defs:
  - `a flat circle has length 2πR within 1%`: 16 points on a radius-200 circle.
  - `frames stay orthonormal`: every sample of the circle and of the loop def below has unit `t`, `n`, `r` within 1e-3 and pairwise dot products under 1e-3.
  - `the up vector turns over inside a vertical loop`: an approach, then a vertical loop of radius 40 offset sideways by 20 m, then an exit. At the loop's top, `n[2] < -0.9`. Back on the flat exit, `n[2] > 0.99`.
  - `roll 2π over a straight makes a corkscrew`: at its midpoint, `n[2] < -0.9`.
  - `a closed loop's up vector meets itself`: on a closed track with hills and banking, the first and last sample's `n` differ by under 1e-2. This checks the parallel-transport twist correction.
  - `curve is positive on a right-hand turn and about 1/R`.
  - `water and gap flags cover their segments' samples`.
  - `checkpoints avoid branch spans and are in increasing order`: a def with one shortcut from segment 3 to 6. No checkpoint lies within that span ±`OPENING`.
  - `frameAt wraps on closed paths`: `frameAt(main, length + 5)` equals `frameAt(main, 5)`.

- [ ] **Step 2: Run** `npm run test`. Expected: FAIL.

- [ ] **Step 3: Implement.** Use a centripetal Catmull-Rom through the points (closed or open), resampled by arc length to every `SAMPLE` m. Compute up by parallel transport starting from world up projected off the tangent. On a closed path, spread the leftover twist linearly over the length, then add the interpolated per-point `roll`. Width, water and gap interpolate from the segments. Branch metres come from the main path's sample at each segment index. `buildTrack` throws if a shortcut has no `side`. Drop branches ignore it, and the built `Branch` gets `side: 1`. Pads convert `seg`/`at` to `s`.

### Task 3: Ship physics

**Files:**
- Create: `src/components/games/race-physics.ts`, `src/components/games/race-physics.test.ts`

**Interfaces:**
- Consumes: Task 1 `Stats`, `LAPS`. Task 2 `Track`, `frameAt`, `sampleIndex`, `PAD_LENGTH`, `PAD_HALF_WIDTH`, `OPENING`.
- Produces:

```ts
export const STEP = 1 / 120
export const SHIP_HALF_WIDTH = 1.2
export type Input = { steer: number /* -1..1, + is right */; throttle: boolean; brake: boolean; boost: boolean }
export type Tuning = { accel: number; top: number; turn: number; grip: number; boostMul: number; kick: number }
export type ShipState = {
  path: number; s: number; x: number; y: number
  yaw: number          // heading relative to the path tangent, + is right
  speed: number        // m/s along the heading
  meter: number        // 0..1
  boosting: boolean
  kickLeft: number     // seconds of pad kick left
  launch: boolean      // touched a launch pad since the last gap
  air: { from: number; to: number } | null
  lastPad: number      // index of the last pad touched, so one pass counts once
  lap: number          // laps finished
  next: number         // index of the next checkpoint
  time: number         // ms since go
  lapStart: number     // ms when this lap started
  laps: number[]       // ms per finished lap
  finished: boolean
}
export type StepEvents = { lap?: { n: number; ms: number; delta: number | null }; pad?: boolean; wall?: number; landed?: boolean; finished?: boolean }
export type Ghost = Pick<ShipState, 'path' | 's' | 'x' | 'y' | 'speed'>

export const PHYS: { boostSeconds: number; refillSeconds: number; padMeter: number; kickSeconds: number; waterTop: number; wallLoss: number; brake: number; drag: number; gravity: number }
export function tuning(stats: Stats): Tuning
export function createShip(track: Track, grid: number /* 0..3 */): ShipState
export function stepShip(track: Track, t: Tuning, st: ShipState, input: Input, dt: number): StepEvents
/** Runs fixed STEPs for one frame. Clamps frameDt to 0.1 s. Returns the leftover for next frame and merged events. */
export function advance(track: Track, t: Tuning, st: ShipState, input: Input, frameDt: number, carry: number): { carry: number; events: StepEvents }
export function bump(track: Track, own: ShipState, other: Ghost): boolean
export function mainDistance(track: Track, st: Pick<ShipState, 'path' | 's'>): number
export function progress(track: Track, st: ShipState): number // lap * mainLength + mainDistance
```

Rules the implementation must follow, beyond the spec:
- `PHYS` starting values: `boostSeconds: 5`, `refillSeconds: 20`, `padMeter: 0.2`, `waterTop: 0.85`. The rest are the implementer's to pick and Task 4 to tune.
- `tuning(stats)` maps 1 to 5 linearly onto ranges with stat 3 in the middle. Vega's `boostMul` is 1.5. Task 4 may change the ranges but keeps the mapping linear.
- Steering: each step, `yaw += steer * turn * dt` and `yaw -= curve(s) * ds`, so the track turning under you pushes you toward the outside unless you steer. Forward motion along the path is `speed·cos(yaw)`, sideways is `speed·sin(yaw)`.
- Walls sit at `|x| = width/2 − SHIP_HALF_WIDTH`. On contact, clamp `x`, set `yaw` toward 0, cut speed by `wallLoss · |sin(yaw)|`, and report `wall` as the fraction lost. No wall exists on a shortcut's `side` for `OPENING` metres after its `from` and before its `to`. Crossing the edge there on the main path moves the ship onto the branch at `s = 0`, `x = −side · (width/2 − 2)`. Reaching the end of a branch moves it onto the main path at `to`, `x = side · (width/2 − 2)`.
- Drop branches: reaching a main gap's first sample with `launch` false moves the ship to the drop branch, `s = 0`, same `x`. With `launch` true, `air = { from, to }` and the ship stays on main with `y = 4·h·u·(1 − u)`, where `u` runs 0 to 1 across the gap and `h = 8`. Then `landed`, `air = null`, `launch = false`. Steering works in the air.
- Pads: when the ship's footprint overlaps a pad (`|Δs| < PAD_LENGTH/2`, `|Δx| < PAD_HALF_WIDTH`), and that pad isn't `lastPad`, apply `meter = min(1, meter + padMeter)`, `kickLeft = kickSeconds`, set `launch` if it's a launch pad, and report `pad`.
- Checkpoints: crossing `checkpoints[next]` forward on main increments `next`. Crossing main `s = 0` forward with `next === checkpoints.length` finishes a lap: push its ms, reset `next = 0`, report `lap` with `delta` from the previous lap (null on lap 1). After `LAPS` laps, `finished`. Crossing backward never counts and never rewinds `next`.
- `bump` acts only when `own` and `other` share a path, `|Δs| < 4` and `|Δx| < 2·SHIP_HALF_WIDTH`. It pushes `own.x` away, the one behind loses 3% speed and the one ahead gains 2%. Returns whether it touched.
- `time` advances only after `createShip`'s owner starts stepping, which happens after the countdown.

- [ ] **Step 1: Write the failing tests** in `race-physics.test.ts`. Build tiny tracks inline with Task 2's `buildTrack`: a 1 km oval, the oval with one shortcut, and a straight with one gap plus its drop branch and a launch pad.
  - `throttle reaches top speed and holds it`.
  - `holding boost drains a full meter in about 5 s, and releasing stops boost the same step`.
  - `the meter refills from empty in about 20 s`.
  - `a pad adds 0.2 to the meter once per pass`.
  - `water lowers top speed to 0.85 of dry`.
  - `with no steering, a turn carries the ship into the outside wall` (`wall` reported).
  - `a head-on wall hit costs more speed than a glancing one`.
  - `a lap counts only after every checkpoint, in order`: driving forward around the oval gives `lap.n === 1`.
  - `crossing the line backward and forward again counts no lap`: from just past the line, drive backward over it, then forward. `laps` stays empty.
  - `lap delta compares with the previous lap`.
  - `three laps finish the race`.
  - `steering into an open shortcut moves onto the branch, and its end rejoins main`.
  - `the shortcut's opening has no wall, the rest of its side does`.
  - `touching the launch pad clears the gap, missing it drops onto the lower road`.
  - `advance clamps a 5 s frame`: one `advance` call with `frameDt = 5` moves the ship no further than 0.1 s of top speed, and it stays between the walls.
  - `bump pushes apart and the ship behind loses speed`.
  - `progress orders a ship on a shortcut against one on main`.

### Task 10: Race rooms on the server

**Files:**
- Create: `api/internal/service/race/room.go`, `api/internal/service/race/room_test.go`, `api/internal/http/handlers/race/socket_test.go`
- Modify: `api/internal/http/handlers/race/race.go`, `api/internal/service/services.go`, `api/internal/http/handlers/handlers.go`, `api/internal/http/routes/public.go`

**Interfaces:**
- Consumes: `CleanName`, `Ships`, `Tracks` from Task 7. `tetris/room.go` is the template for the hub, codes, seats, host hand-over, `Shutdown` and `MaxRooms`.
- Produces: `NewHub(Timing)`, `Default = Timing{Countdown: 3 * time.Second, Cutoff: 30 * time.Second, MaxRace: 8 * time.Minute}`, and `Hub.Create` / `Hub.Join` / `Room.Pick` / `Room.Start` / `Room.State` / `Room.Finish` / `Room.Leave`. Socket at `GET /api/race/ws` with `gameLimiter()`, plus a `gamesocket.Config{ReadLimit: 512, SendQueue: 256, MaxMessagesPerSecond: 40}`.

Messages (client → server):

| Message | Meaning |
|---|---|
| `{"t":"create"}`, `{"t":"join","code":"ABCD"}` | First message |
| `{"t":"pick","ship":"vega","name":"Bat"}` | Lobby only. Refused with an error if invalid |
| `{"t":"start"}` | Host, lobby, at least 2 seats that have picked |
| `{"t":"s","p":0,"d":512.3,"x":-2.1,"y":0,"h":0.05,"v":81.2,"b":1,"l":1,"c":3}` | Ship state, about 20/s |
| `{"t":"finish","ms":204118}` | Crossed the line on lap 3 |

Messages (server → client):

| Message | Meaning |
|---|---|
| `{"t":"room","code","you","host","seats":[bool×4],"names":[…],"ships":[…],"wins":[…],"racing":[bool×4],"playing":bool}` | After any change |
| `{"t":"race","round","track":"skyway","count":3000,"players":[bool×4]}` | Countdown starts. Track from the room's shuffle bag, never the same twice in a row |
| `{"t":"s","s":2,…}` | A relayed state with its seat |
| `{"t":"done","s":2,"ms":204118,"place":1}` | Someone finished |
| `{"t":"over","order":[2,0,1,-1],"ms":[204118,209877,-1,-1],"win":2,"wins":[…]}` | Race over. `order` is seats by place, with DNF seats at -1 after the finishers. `ms` lines up with `order` |
| `{"t":"error","msg":"…"}` | Refused |

Rules: states are relayed only while running and only from seats racing this round, and dropped silently if a number isn't finite or is out of a sane range (`p` 0 to 15, `l` 0 to 3, `c` 0 to 64, `|d|,|x|,|y|,|v|` under 1e5). `finish` counts once per seat, and finish order is arrival order. The first finish starts the `Cutoff`. The race ends when every racer has finished or left, or the cut-off fires, or `MaxRace` passes since the countdown ended. Leaving mid-race makes a seat DNF. A seat joining mid-race watches. Each round's timers are tied to the round number, like Tetris's `clock`, so a stale timer does nothing.

- [ ] **Step 1: Write the failing tests** in `room_test.go`, reusing Tetris's `inbox` helper pattern: create, join, full room. `pick` refuses a bad name or ship. Start refuses a non-host, fewer than 2 picked seats, or an ongoing race. `race` names a track and two consecutive races differ. States relay to others but not back to the sender, and not from a watcher or outside a race. A NaN-free but out-of-range state is dropped. Finish order and `done` places. The cut-off ends a race with DNFs. Everyone finishing ends it early. The host leaving mid-race hands over host and marks DNF. The last racer leaving ends the race. `MaxRace` ends a race nobody finishes. A joiner mid-race isn't in `players`. In `socket_test.go`, over a real socket like Tetris's handler test: a foreign Origin gets 403, and create, join, pick, start and a relayed state work end to end.
- [ ] **Step 2: Run** `cd api && go test ./internal/service/race/... ./internal/http/handlers/race/...`. Expected: FAIL.
